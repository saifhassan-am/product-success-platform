# Product Success Platform

Know which stage every customer site is at in every Thrive product, and give support a short daily list of customers they can help move forward.

* **Overview:** <https://saifhassan-am.github.io/product-success-platform/>
* **Spec:** <https://saifhassan-am.github.io/product-success-platform/spec/> (source: [SPEC.md](SPEC.md))
* **Demo, in your browser:** <https://saifhassan-am.github.io/product-success-platform/demo/>

Every person, site and number in the demo is invented, and every domain uses the reserved `.example` name.

## What's here

| Path | What it is |
|---|---|
| [`SPEC.md`](SPEC.md) | The product spec: the five stages, what we track, consent, the support console, and the pilot. |
| [`demo/`](demo/README.md) | A working model: the WordPress-side client, ingestion, the stage engine, the support console and a live simulator. PHP and SQLite, nothing else. |
| `site/` | The overview page, the spec page template and styles, and the pieces that turn the demo into a browser-only copy. |
| `docs/` | The built GitHub Pages site. Generated by `build.sh`; don't edit it by hand. |

## Run the demo locally

The browser copy is a snapshot. Run it locally for the **Live** switch and the simulator that walks a site through every stage. You need PHP 8.1 or newer with `pdo_sqlite` and `curl`.

```bash
cd demo
```

```bash
php bin/seed.php
```

```bash
php -S 127.0.0.1:8787 -t public public/router.php
```

Then open <http://127.0.0.1:8787/console/index.html>. [demo/README.md](demo/README.md) has the simulator walkthrough and things to try.

## Rebuild the site

Needs PHP 8.1 or newer and [pandoc](https://pandoc.org) 3.

```bash
./build.sh
```

This re-seeds the demo data, so dates stay relative to the day you build. Commit `docs/` afterwards; GitHub Pages serves it from the `main` branch as is.
